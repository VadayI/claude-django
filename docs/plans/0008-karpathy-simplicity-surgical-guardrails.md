# План 0008 — Karpathy-guardrails: «Simplicity First» + «Surgical Changes»

**Джерело:** репозиторій `multica-ai/andrej-karpathy-skills` (MIT) — один `CLAUDE.md` із 4 поведінковими принципами за твітом А. Карпаті про типові помилки LLM-кодингу. Аналіз від 2026-06-05.
**Мета:** додати в шаблон дві поведінкові дисципліни, яких у ньому **немає явно сформульованими**, у вигляді одного короткого правила — без тягнення зовнішнього плагіна/скіла.
**Природа змін:** лише конфіг/документація шаблону (`.claude/rules`, `CLAUDE.md`, агент `reviewer`, ADR, WORKLOG). **Немає** коду, моделей, міграцій, тестів → це НЕ feature-pipeline. Іде однією гілкою `chore/karpathy-guardrails` → PR (правило `git-operations.md`, прямого пушу в `main` не робимо).
**Редагування файлів:** на цьому mount інструменти Edit/Write обрізають файли — усі правки робляться через `bash` heredoc.

## Контекст рішення (що беремо і чого НЕ беремо)

Репозиторій — це **один документ**, запакований тричі (`CLAUDE.md`, Cursor-rule, один Claude Code skill `skills/karpathy-guidelines`). Не колекція агентів/скілів.

Зіставлення 4 принципів зі станом шаблону:

| Принцип Карпаті | Стан у claude-django | Дія |
|---|---|---|
| 1. Think Before Coding | Покрито: Plan Mode, `AskUserQuestion`-гейт, triage у `workflow.md`, агент `devil` | НЕ дублюємо |
| 2. **Simplicity First** | Частково: `reviewer` має рядок «no premature abstractions», але немає правила-настанови «мінімальний код, без спекулятивних абстракцій» | **Додаємо** |
| 3. **Surgical Changes** | Відсутнє: немає правила «кожен змінений рядок трасується до запиту; не чіпай сусіднє» | **Додаємо** |
| 4. Goal-Driven Execution | Покрито глибше: `tdd.md` (double-loop), `verification.md`, success-criteria | НЕ дублюємо |

**Свідомо відхилено:**
- Підключати плагін `andrej-karpathy-skills@karpathy-skills` або копіювати його skill — generic мова-агностичний текст дублює наявне; як *skill* не тригериться (це «завжди»-настанова, місце якій у `rules/`, а не в `skills/`); зайва зовнішня залежність заради 2.3 КБ.
- Копіювати принципи 1 і 4 — уже покриті, дублювання порушило б «Simplicity First».

## Крок 1 — нове правило `.claude/rules/simplicity-surgical.md`

**Що:** один короткий файл (ціль ≤ ~60 рядків — саме правило має бути зразком «Simplicity First») із двома секціями.

- **Simplicity First** — мінімум коду на вирішення задачі; без фіч понад запит; без абстракцій для one-use коду; без «гнучкості/конфігурованості», якої не просили; без обробки неможливих сценаріїв. Тест: «чи сказав би senior, що це переускладнено?». Адаптувати під Python/Django (приклад: не плодити service-layer/strategy там, де достатньо методу моделі — пор. `architecture.md` «thin views, rich models»).
- **Surgical Changes** — чіпати лише потрібне; не «покращувати» сусідній код/коментарі/форматування; не рефакторити те, що не зламане (для цього є `/structure-audit` і `django-refactoring-expert` під зеленими тестами); тримати наявний стиль. Прибирати тільки **власні** орфани (імпорти/змінні, які зробили зайвими твої зміни); чужий dead code — згадати, не видаляти. Тест: кожен змінений рядок трасується до запиту користувача.

**Крос-посилання (щоб не дублювати, а зшити):** `no-stubs.md` (стуби — тимчасові, не «про запас»), `tdd.md` (мінімальний GREEN), `code-style.md` (малі функції, без magic numbers), `git-operations.md` (один branch = одна логічна зміна).

**Перевірка:** `wc -l` правила невеликий; читається як настанова, не як процес; жодного повтору принципів 1/4.

## Крок 2 — підключити правило в `CLAUDE.md`

**Що:** дописати `@.claude/rules/simplicity-surgical.md` в import-блок угорі `CLAUDE.md` — логічно одразу після `@.claude/rules/code-style.md`.
**Чому туди:** воно про стиль/обсяг змін, поряд із code-style; не плутати з process-правилами (`workflow`, `preflight`).
**Перевірка:** `grep simplicity-surgical CLAUDE.md` → один рядок; порядок імпортів логічний.
**Ризик:** забути синхронізувати коментар «Last reviewed/updated» унизу `CLAUDE.md` — оновити дату й рядок змін.

## Крок 3 — докрутити агента `reviewer`

**Що:** розширити наявний пункт «Simplicity: no premature abstractions» у `.claude/agents/reviewer.md` до явної перевірки обох дисциплін на Quality Gate:
- *Simplicity* — позначати оверінжиніринг (зайві абстракції, спекулятивна конфігурованість) як 🟡.
- *Surgical diff* — позначати drive-by зміни поза запитом (рефактор сусіднього коду, переформатування, видалення чужого dead code) як 🟡; вимагати, щоб кожен змінений рядок трасувався до задачі PR.

Додати посилання `@.claude/rules/simplicity-surgical.md` у блок «What you check».
**Перевірка:** опис у frontmatter не ламається; правило згадане; класифікація 🔴/🟡/🟢 збережена.
