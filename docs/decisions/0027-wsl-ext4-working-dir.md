# 0027 — Робочий клон у файловій системі WSL (ext4); сесія агента на `/mnt` — лише з явним дозволом

- Статус: прийнято
- Дата: 2026-10-22
- Supersedes: ADR `0009` («Робота з /mnt повноцінно підтримується»)
- Рішення плану: D11 (розташування), D12 (повний прогін тестів), D17 (блокування сесії на `/mnt`)

## Контекст

ADR `0009` оголосив роботу з проєктом на Windows-диску (`/mnt/c`, `/mnt/d`) штатним
сценарієм, а повільні bind-mount'и — косметикою. Заміри на реальному похідному проєкті
показали, що це не косметика, а головна причина довгих прогонів:

| Операція | Репо на `D:` (`/mnt/d`, 9P) | Репо на ext4 (`~/src`) |
|---|---|---|
| Повний `pytest` | 55 хв | 1 хв 37 с |
| Збірка образу | 36 хв | 41 с |
| `pytest-xdist`, 16 воркерів | CPU 83 % із 1600 %, 12 хв простою на старті | масштабується |
| Контекст збірки без `.dockerignore` | 386 МБ медіа | — |

Причина: Docker Desktop працює всередині WSL2; bind-mount `./backend:/app` з Windows-диска
читає кожен файл через міст Windows → WSL (9P/drvfs). Тисячі дрібних звертань (імпорти
модулів, `node_modules`, `.git`, hot reload) коштують мілісекунди кожне замість мікросекунд.
Паралельність на 9P нічого не дає: воркери серіалізуються на I/O.

Діагностика, яку може повторити будь-хто:

- `time ls -R /mnt/d/<repo> >/dev/null` проти `time ls -R ~/src/<repo> >/dev/null` — різниця 10–50×;
- `docker stats` під час тестів: CPU значно нижчий за 100 % × кількість ядер при живих
  процесах = процеси чекають на диск, а не рахують.

## Рішення

1. **Робочий клон живе в ext4 WSL** (`~/src/<repo>`). Git, Docker, pip/npm, тести, Claude Code
   і Codex запускаються з WSL у цьому клоні; VS Code — через Remote-WSL. Windows-диск — лише
   для даних Windows-програм; великі дані з нього монтуються в контейнер окремо й read-only.
2. **D17 — сесія агента на `/mnt` блокується** без явного дозволу користувача на цю сесію:
   `scripts/ai/workdir.py` (спільне ядро) визначає Windows-диск за шляхом `/mnt/<диск>` або
   типом mount `9p`/`drvfs`. Без `ALLOW_MNT_SESSION=1` у середовищі агента hook'и
   `UserPromptSubmit` і `PreToolUse` повертають exit 2 з поясненням і чек-листом перенесення;
   `session_context.py --check` дає exit 1; `/doctor`, `/bootstrap`, `/adopt`, `/wrap-up`
   зупиняються на кроці 0. З дозволом сесія продовжується, а дозвіл записується в рекорд
   сесії (Limitations). Дозвіл не зберігається в налаштуваннях проєкту. Нативний Windows і
   macOS під D17 не підпадають.
3. **`/doctor`**: репо на `/mnt` → ⚠️ з чек-листом і евристикою (`time ls -R`, `docker stats`);
   ext4 → ✅. На нативному Windows із Docker bind-mount з диска `C:`/`D:` — ⚠️ з тією ж
   порадою (той самий міст), але без блокування.
4. **`.dockerignore` з першого коміту** (`templates/.dockerignore`): медіа, кеші, `.git`,
   `node_modules`, `.venv`, `.env*`.
5. **`pytest-xdist`** у dev-залежностях; `make ci` / `make test` запускають
   `-n auto --dist loadfile`. Виграш — лише на ext4; на `/mnt` xdist погіршує.
6. **D12**: повний прогін — не частіше двох разів на день і запускає його користувач; агенти
   дають готову команду й самі запускають лише цільові підмножини (`-k`, змінені модулі, `--lf`).
7. Якщо перенос неможливий одразу — мінімум окремий test-клон на ext4 для `make ci`/pre-push з
   власним `COMPOSE_PROJECT_NAME`.

Чек-лист перенесення (8 кроків) — `docs/ai/wsl-ext4-migration.md`; його ж друкує `workdir.py`.

## Наслідки

**Плюси.** Повний прогін — хвилини замість години; збірка — секунди; xdist реально
масштабується; агенти не працюють у середовищі, де кожна перевірка коштує десятки хвилин.

**Мінуси.** Одноразовий перенос існуючих клонів; Windows-інструменти бачать код через
`\\wsl$\...`. Користувач, який свідомо працює на `/mnt`, мусить щоразу запускати агента з
`ALLOW_MNT_SESSION=1`. Якщо в WSL немає `python3` (або `AI_PYTHON`), hook не стартує, і
Claude Code вважає це неблокувальною помилкою — бар'єр тоді тримається лише на кроці 0
команд і на `session_context`.

**Не перевірено (NOT_VERIFIED).** Швидкість самого Claude Code CLI у WSL на ext4 (п. 8 етапу
P08a) — вимір виконує користувач; результат записується в STATUS, не припущення.

**Відкинуті альтернативи.** Лишити ADR `0009` з ⚠️ замість блокування — відхилено: попередження
вже ігнорувалося, а ціна — година на кожен прогін. Постійний прапорець у налаштуваннях
проєкту — відхилено: дозвіл має бути свідомим рішенням на одну сесію.
